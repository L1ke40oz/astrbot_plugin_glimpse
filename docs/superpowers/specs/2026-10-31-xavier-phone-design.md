# 沈星回的手机（astrbot_plugin_glimpse）设计文档

日期：2026-10-31
状态：已通过审查，待用户最终确认
仓库：https://github.com/L1ke40oz/astrbot_plugin_glimpse（本地位于 `data/plugins/astrbot_plugin_glimpse`，当前仍是 helloworld 模板，实现时要替换 `main.py`、`metadata.yaml`、`README.md`）

## 1. 意图与动机

用户在 AstrBot 里和人设「沈星回」（《恋与深空》角色）文字聊天。人设里已经允许他用 `[📷分享图片：…]` 这类方括号文字来“分享照片”，但这些只是文字。

本插件把聊天里**文字做不到的视觉内容**变成真图，让用户感觉他确实有自己的生活：他拍下阳台上的小鸟、邱诺亚花店的花、旅行路上的海，或者闲着随手画一张 QQ 人涂鸦发过来。

长期设想：所有生成的图都存进“相册”，以后做一个像小手机的前端页面，可以翻照片、看画板。第一版只把数据存好，不做前端。

## 2. 目标

1. **相机**：他分享景色、小动物、物件时，生成一张真实感的手机照片。
2. **胶片相机**：相机的一种变体，偶尔使用，属于惊喜。
3. **涂鸦**：他闲着随手画的 QQ 人风格简笔画（圆脑袋、粗黑线、白底、几笔画完），内容是他自己的日常。
4. **固定场景**：在他的公寓（卧室/厨房/客厅/露台）和「邱诺亚的花店」拍照时，用参考图做图生图，保证房间长得和游戏里一样。
5. **自由场景**：其他地方（出门、旅游、海边、路上）只用文字生成，不受参考图限制。
6. **相册数据**：每张成功生成的图连同元数据一起保存，为以后的手机前端做准备。

## 3. 非目标（第一版不做）

- 自拍或任何露出他本人的照片。涉及他自己的内容继续发文字版 `[📷分享图片：…]`。
- 合照（人设规定两人无法物理接触）。
- 视频、衣服/鞋子参考图（以后可能加）。
- 小手机前端页面、WebUI 配置页面（只用 AstrBot 原生的 `_conf_schema.json` 配置）。
- 多家生图服务、备用节点链路。只接一个 OpenAI 兼容的 gpt-image 中转站。
- 生图前用小模型“扩写”提示词（先看第一版效果，不够再加）。
- 主动定时发照片。
- 聊天指令。

## 4. 反目标（就算能跑也算失败的情况）

- 画面里出现人脸或手（第一人称随手拍，只拍他看到的东西）。
- 用户看到长串提示词、英文标签、报错信息，或者残缺的方括号标记。
- 先发“我拍给你”，过很久才来图，节奏被打断。
- 公寓被生成成宫殿或别的不像他家的地方。
- 每次带参考图都拍出和参考图一模一样的全景，失去新鲜感。
- 插件故障导致他的整段回复发不出来。

## 5. 约束

- 运行环境：AstrBot `>=4.16,<5`，Python 3.10+，需兼容 Windows/macOS/Linux。
- 用户当前配置：流式输出**关闭**；分段回复**开启**，`split_mode=regex`、`regex="[^$]+"`、`content_cleanup_rule="[$]"`，即他用 `$` 分隔消息单元。
- 作用范围：这个 bot 只供用户和沈星回聊天使用，插件**对所有会话全局生效**，不按人设或会话做过滤；每日上限也按全局计数。
- 生图服务：OpenAI 兼容中转站（地址由用户在配置中填写），模型 `gpt-image-2.5`（按次计费），走 OpenAI 兼容接口。该站基于 new-api 网关，`/images/edits` 是否支持一次传多张参考图无法从公开信息确认，**实现时必须实测**：如果不支持多图，场景库就改为每次只传一张，即按时间挑出的那一张；没有带时段的图时传文件夹里的第一张。文生图走 `POST {base_url}/images/generations`（JSON）；图生图走 `POST {base_url}/images/edits`（multipart，多张参考图用 `image[]`）。返回可能是 `b64_json` 或 `url`，两种都要处理。可参考 `astrbot_plugin_omnidraw/providers/openai_impl.py` 与 `providers/base.py` 的写法，但不要整套搬过来。
- 项目规范（见 AstrBot `AGENTS.md`）：KISS，不加不必要的 helper；用 `pathlib.Path`；注释和日志用英文；docstring 用 Google 风格；用 `ruff format` / `ruff check`。
- 插件数据目录：`data/plugin_data/astrbot_plugin_glimpse/`。AstrBot 中并没有 `path_utils` 模块，应使用 `astrbot.core.utils.astrbot_path.get_astrbot_plugin_data_path()` 或 `StarTools.get_data_dir()` 获取，不要硬编码。
- 分段回复只拆分长度不超过 `words_count_threshold` 的 `Plain`（用户当前设为 995），更长的文字会整段发出。按标记拆开 `Plain` 只会让片段变短，所以对分段没有坏处。
- 模型调用其他工具时，每个中间 LLM 结果都会单独经过发送前钩子，所以“每条回复最多 3 个标记”按每次产出的消息计，而不是按整轮对话计。这一点可以接受。
- 钩子内的异常会被 AstrBot 捕获并记录，回复仍会发出；但实现时要保证要么整条消息链都替换成功，要么都不改动，不能发出改了一半的消息链。

## 6. 方案比较（已选定 B）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 注册 LLM 工具 | 每种内容一个 `@llm_tool`，模型主动调用 | 结构清晰，扩展方便 | AstrBot 调完工具会再调一次模型，每张图多一轮延迟和花费；会打断 `$` 分段节奏；用户的模型本来就不太爱主动调用 |
| **B. 识别回复里的标记** | 在发送前钩子里，把他回复中的特定方括号标记替换成真图 | 贴合人设已有习惯；不额外调用模型；图片出现在原句位置 | 需要教他新标记；需要宽松解析和失败回退 |
| C. A + B 都做 | — | 两种触发都能用 | 复杂度翻倍，目前没有必要 |

**用户选择 B**，理由：最贴合现有人设写法、最省钱、最不出戏；只有新标记才生图，自拍类的旧标记 `[📷分享图片]` 自然保持为文字。以后换了更爱调工具的模型，再补 A 也不难，生图部分可以共用。

## 7. 用户已确定的设计

### 7.1 标记与触发

- 他在回复里写新标记，插件识别后生图。旧的 `[📷分享图片：…]` **不处理**，原样保留为文字。
- 三种标记：
  - `[📷拍照：描述]` / `[📷拍照·场景名：描述]`：相机
  - `[🎞️胶片：描述]` / `[🎞️胶片·场景名：描述]`：胶片相机
  - `[✏️涂鸦：描述]`：涂鸦
- 描述是一两句自然的中文，写清主体、环境和光线，例如 `[📷拍照·公寓-露台：吊椅上睡着一只橘猫，星星灯刚亮]`。这句话同时是失败时的文字回退内容，所以永远是给人看的话。
- **宽松解析**：全角/半角冒号都认；emoji 可有可无；“拍照/照片”都认；“·”和“-”等分隔符都认。场景名写错或不存在时，当作自由场景（纯文生图），不报错。不像标记的内容原样保留。

### 7.2 先生成、再发送

- 在 `@filter.on_decorating_result()` 钩子里处理：只处理 LLM 结果（`result.is_llm_result()`），只扫描 `Plain` 组件。
- 找到标记后先生成图片，**等图片好了，文字和图片按原顺序一起发出**。用户看到的效果是他“晚回了一会儿”，然后话和照片一起到。
- 替换方式：把含标记的 `Plain` 拆成 `[Plain(标记前), Image, Plain(标记后)]`。该钩子在分段回复之前执行，分段时非 `Plain` 组件会原样保留在原位，所以图片会作为单独一条消息出现在对应的 `$` 片段之间。
- 同一条回复里有多个标记时并发生成。

### 7.3 失败回退

以下情况一律把标记替换为文字回退，不让用户看到异常：
- 生图失败（网络错误、接口报错、返回无图）
- 超过最长等待时间（配置项，默认 90 秒）
- 超过每日上限
- 生图服务未配置

回退文字：相机和胶片回退为 `[📷分享图片：描述]`；涂鸦回退为 `[✏️涂鸦：描述]`（看起来就是他发了一句带标记的文字）。错误只写进日志。

### 7.4 两层提示词

- **第一层**：他写的一句自然话（标记里的描述）。
- **第二层**：插件按标记类型套上固定的英文模板，用户永远看不到。gpt-image 擅长理解完整句子，不需要堆叠短词标签。
- **相机模板**要点：手机随手拍质感、第一人称视角、**画面中不出现人脸和手**、自然光且不过度修图、按当前时间配合白天或夜晚的光线，以及防翻车约束（透视合理、无塑料感、无多余文字或水印）。
- **胶片模板**：在相机模板基础上换成胶片质感，比如颗粒、轻微漏光和偏色。
- **涂鸦模板**：QQ 人风格、粗黑线、白底、像在手机备忘录或纸上随手画；画中的“他”有固定小特征：一撮银色呆毛、一颗虎牙。画面里不出现文字说明（这一点为建议，见第 8 节）。
- **带参考图时**额外加一句：这是同一个房间，换个角度或聚焦某个局部，不要复刻参考图的全景构图。
- 模板写在插件代码里作为常量，第一版不开放配置。

### 7.5 场景库（图生图）

- 一个子文件夹 = 一个场景，**文件夹名就是场景名**。往里放图即可新增场景，不用改代码或配置。
- 用户已整理好的场景：
  - `公寓-卧室/夜晚.jpg`
  - `公寓-厨房/厨房.jpg`
  - `公寓-客厅/夜晚.jpg`、`公寓-客厅/白天.jpg`、`公寓-客厅/客厅全景.jpg`
  - `公寓-露台/夜晚.jpg`、`公寓-露台/白天.jpg`
  - `邱诺亚的花店/夜晚.jpg`、`邱诺亚的花店/白天.jpg`
- **按时间挑图**：文件名含“白天”或“夜晚”的图只在对应时段使用；其他文件名的图总是带上。如果按规则筛完一张都不剩（比如卧室只有夜晚图、现在是白天），就用该文件夹里的全部图。
- 场景库目录做成配置项，默认为插件数据目录下的 `scenes/`。

### 7.6 让他知道怎么用

- 在 `@filter.on_llm_request()` 里向 system prompt 追加一段简短说明，内容包括：
  - 三种标记的写法
  - 当前可用的场景名列表（从场景库目录读取）
  - “涉及自己的照片继续用 `[📷分享图片]` 文字版”
  - “按心情偶尔使用，不必每次都发”
- 这样用户的人设文件不用改。说明文字作为配置项提供默认值，可在配置里修改。

### 7.7 每日上限

- 配置项“启用每日上限”默认**关闭**，即按他的心情决定发多少；开启后填写每天最多生成的张数。
- 超出上限的标记走文字回退。计数按自然日，从相册数据统计即可。

### 7.8 相册数据

- 每张成功的图保存到插件数据目录的 `album/`，同时追加一条元数据，包括：类型（拍照/胶片/涂鸦）、场景名（可空）、他写的描述、实际发送的完整提示词、使用的参考图文件名、生成时间、会话 ID（`unified_msg_origin`）、图片文件名。
- 存储格式由实现者决定，建议用 JSON Lines，简单、方便追加。

### 7.9 配置项（`_conf_schema.json`）

- 生图服务：`base_url`、`api_key`、`model`、`timeout_seconds`（默认 90）
- 尺寸：相机/胶片默认竖图（如 `1024x1536`），涂鸦默认方图（`1024x1024`）
- 场景库目录（默认插件数据目录下的 `scenes/`）
- 启用每日上限（默认 false）、每日张数
- 注入给他的使用说明（有默认值）

## 8. 我替用户做的决定（请过目）

- 不复用 omnidraw 整个插件，只参考它的接口调用写法自己重写。
- 胶片不是一个独立工具，而是一种独立标记，和相机共用模板，只是加了胶片质感。
- 使用说明由插件自动注入，而不是让用户手改人设文件。
- “白天”指本机时间 6:00–18:00，其余为“夜晚”。
- 每条回复最多处理 3 个标记，超出部分走文字回退，防止模型失控刷屏。
- 涂鸦里不放文字说明（gpt-image 画中文字容易出错）。
- 第一版不做聊天指令和 WebUI 页面。

## 9. 留给实现者决定的事

- 模块怎么拆分。保持精简，遵守 AGENTS.md 的“不要不必要的 helper”。
- 正则的具体写法；英文模板的具体措辞（需满足 7.4 的要点）。
- 相册的文件命名、元数据格式细节，以及 HTTP 客户端的会话管理。
- 测试：至少为标记解析、按时间挑选参考图、回退文字这三块写单元测试；用真实中转站手动跑一遍端到端。

## 10. 第二轮迭代（2026-11-01，已与用户确认）

真机试用后，用户提出了以下补充（第 3 节里“第一版不做”的部分内容由此解禁）：

- **已上线的小改动**：照片比例（拍照 3:4、胶片 3:2、涂鸦 1:1，先裁参考图，生成后居中裁切兜底）；去 CG 提示词，并保留旧版作为「氛围大片」画风选项；备用生图节点按顺序回退，每个节点各自计时；配置页显示注入的使用说明全文，并提供开关。
- **物件/宠物参考库**：一个子文件夹 = 一个物件，文件夹名即名字（如 `芝士`、`蛋挞`，他养的赛博猫）。描述里出现这个名字，就自动带上该物件的第一张图。使用说明里列出所有物件名（占位符 `{objects}`）。
- **按作息换装**：服装文件夹名为 `类别-名称`，类别为 `制服`、`便服`、`睡衣`。工作日 9–18 点穿制服；23 点到次日 7 点穿睡衣；其余时间穿便服。时间点可配置。同一类别按日期固定挑一套（`date.toordinal() % 数量`）；某类别没有衣服时从全部衣服里挑。当前穿着写进使用说明（占位符 `{outfit}`），让他的文字与照片一致。
- **露手开关**（默认关）：开启后，只有描述里写到他自己的手或袖子（关键词：我的手、我手里、我手上、我手中、手中的、双手、指尖、掌心、袖子、袖口、胳膊、手臂；不用单字“手”“袖”或“手指”，避免误匹配“手机”“袖珍”“手指饼干”）时，才带上当前衣服的第一张图和手部参考的第一张图，提示词允许出现手、前臂和袖子；任何情况下都不出现脸。
- **季节**：按月份在拍照和胶片的提示词里加上季节（北半球：3–5 春、6–8 夏、9–11 秋、12–2 冬）。
- **参考图标注**：提示词按顺序说明每张参考图是什么（物件要保持外观、衣服和手要匹配、房间只参照布局）。参考图名额优先级：物件 > 衣服和手 > 场景，总数不超过「每次最多带几张参考图」（默认改为 4）。
- **配置分组**：用 `object` 分为「生图服务」（含备用节点列表）、「照片」、「参考图库」、「作息换装」、「每日上限」、「使用说明」六组。旧的平铺配置不做代码兼容，由一次性手动迁移用户的配置文件解决。

## 11. 第三轮迭代（2026-11-01，已与用户确认）

- **地点列表合并**：使用说明里的 `{scenes}` 按“-”前的部分分组，如「公寓（卧室/厨房/客厅/楼下/露台）」。标记里的场景名中，`·`、`・`、`—` 一律视为 `-`，所以 `公寓·客厅` 也能匹配 `公寓-客厅`。
- **自拍规则**：使用说明明确“镜头里永远拍不到你：脸、头发、肩膀都拍不到；自拍、对镜、你出现在画面里的照片一律用 `[📷分享图片：…]`”。拍照和胶片的提示词补上“不出现头发、肩膀”。
- **换装标记**：他在回复里写 `[👕换装：衣服名]` 时，插件删掉这个标记（用户看不到），并记下换装。换装持续到下一个作息切换点（类别发生变化的那个整点）为止。衣服名必须是服装目录里存在的文件夹名，否则忽略。使用说明新增占位符 `{wardrobe}`，列出当前类别的可选衣服。换装状态存放在插件数据目录的 `outfit_override.json` 里。用户要求换衣服时，由他按人设决定是否写换装标记，插件只跟随他。
- **露脸防护**（配置最底部的可选分组，默认全部关闭）：
  - 关键词拦截：描述里含有可配置关键词（默认：自拍、镜子、镜中、对镜、合照、出镜、我的脸）时不生成，退回文字。
  - 出图检查：生成后调用看图模型（从 AstrBot 已配置的模型服务商中选择，留空用当前对话模型）判断是否有人脸或头发；回答“是”就丢弃图片、退回文字。检查本身失败时放行，以免一次网络错误就吞掉照片。
- **提示词全部进配置**：新增「提示词」分组，包含拍照、胶片、涂鸦、氛围大片四个模板，白天、夜晚、氛围大片夜晚三条光线，两种参考图说明，露手说明，地点说明，说明里的露手开/关两句，以及出图检查的提问。默认值就是代码里的常量，留空则使用内置版本。参考图角色描述和季节词属于结构性内容，保留在代码里。
- **配置顺序**：生图服务、照片、参考图库、作息换装、每日上限、使用说明、提示词、露脸防护（最底部）。新增的分组由 AstrBot 自动补上默认值，不需要手动迁移。
